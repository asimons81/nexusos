### 5.4 RC-03 MCP client compatibility (Streamable HTTP + raw JSON-RPC)

Validated against the wheel installed in a clean venv (`/tmp/nxo-rc-venv`,
Python 3.11, outside the repository). The same protocol tests also run in
the repository suite (`tests/integration/test_mcp_streamable_http.py`,
`tests/integration/test_mcp_raw_jsonrpc_client.py`) and pass from source.

Documented CLI path — `nexusos serve --transport streamable-http
--workspace <ws> --port <p>` on `127.0.0.1`:

- Server startup: listens on `127.0.0.1:<port>` endpoint `/mcp`.
- Handshake via official MCP Python SDK: `nexusos 0.1.0-alpha.3`.
- Tool discovery: 8 tools — `browse, context, index, links, read, recent,
  search, status`.
- Strict schemas: every advertised tool `inputSchema` has
  `additionalProperties: false`; required args (`search.term`,
  `read.item`, `context.item`, `links.item`) are advertised.
- `status`: `status: ready`, `read_only: true`, `server_version:
  0.1.0-alpha.3`, `index_schema_version: 2`.
- `search`, `read`, `context`, `index` calls return valid JSON text +
  structured content; extra arguments are rejected as tool errors.
- Source immutability: source bytes identical after retrieval + index calls.
- Shutdown: SIGTERM terminates the server cleanly.

Second representative client — raw JSON-RPC over HTTP (stdlib `urllib`, no
MCP SDK): initialize handshake, `tools/list`, `tools/call` for status and
search, session affinity across POSTs, and strict-schema rejection all pass
against the `/mcp` endpoint.

## 6. Environment notes and limitations

- Clean install validated on Linux (Arch, GEEKOM) from the `0.1.0a3` wheel
  and sdist in fresh venvs (2026-08-05). macOS/Windows clean installs remain
  pending RC-02; CI runs the full suite (unit + integration + security +
  contracts) on Linux/macOS/Windows × 3.11/3.12/3.13 and is green on `main`.
- MCP protocol behavior verified via stdio smoke from the installed wheel
  (initialize/discovery/status) and, previously, the full RC-03 client
  matrix (Streamable HTTP with the official SDK + raw JSON-RPC) and RC-04
  upgrade/schema validation (see §5.4–§5.5). Those integration tests also
  run in the repository suite (`tests/integration/`) and pass on this commit.
- RC-04 fix included: read-only commands on a database written by a newer
  NexusOS schema refuse with "newer than supported" instead of the backwards
  "requires upgrade" message.
- PyPI publication remains maintainer-only (no credentials in environment);
  release gate card `t_4715ab1e` owns that step.
- The inspection UI is a single static `index.html`; no JS asset bundle is
  produced, so the wheel's `nexusos/ui/**` glob resolves to that one file.
