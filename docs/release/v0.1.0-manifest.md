## 7. How to reproduce

The commands below reproduce the source tree and validation procedure for the
published tag. A fresh archive can have a different SHA-256 because hatchling
records archive metadata; verify the published assets against the authoritative
hashes in §2 instead of expecting a new build to be byte-identical.

```bash
git clone https://github.com/asimons81/nexusos.git
cd nexusos
git checkout v0.1.0-rc.1
uv sync
rm -rf dist build
uv run --with build python -m build
uv run --with twine twine check dist/*
sha256sum dist/*
```

The RC tag is a lightweight tag despite the Stage 1 procedure calling for an
annotated tag. Published tags are immutable release history, so it is preserved
and documented rather than rewritten. The stable `v0.1.0` gate still requires
the verified/signed tag defined in `docs/release/v1-build-spec.md`.

The published RC sdist predates the stable-build correction that excludes this
mutable ledger from archives. Its embedded copy necessarily contains an earlier
sdist size/hash because writing the final hash changes the archive itself. The
external GitHub asset digest and `SHA256SUMS` are authoritative. Stable builds
exclude this file and attach the finalized ledger/checksums beside the artifacts.
