# NexusOS v0.1 — Release Notes

**Status:** pre-release — `v0.1.0-alpha.3` shipped; release candidate validation next
**Runtime version:** `0.1.0-alpha.3` · **Package version:** `0.1.0a3`
**Source:** [CHANGELOG.md](../../CHANGELOG.md) · [Install guide](../install.md)

NexusOS is a local-first, read-only knowledge index for Markdown vaults. It
scans a folder of Markdown and plaintext files, builds a versioned
SQLite/FTS5 index, and exposes search, navigation, linting, and an MCP server —
without ever mutating your source files.

This is the v0.1 release-train note. It is written from the merged changelog
and the verified artifact manifest
([docs/release/v0.1.0-manifest.md](../release/v0.1.0-manifest.md)).

---

## What is in v0.1

The planned v0.1 core feature scope is implemented across the alpha.1 and
alpha.2 milestones, plus the A3-01 release-hardening fixes landed on `main`
after alpha.2.

### Workspace and configuration

- safe workspace initialization with `blank` and `starter` templates
  (`nexusos init`, with `--template`, `--dry-run`, `--adopt`)
- workspace identity generated with cryptographically secure random IDs
- path boundaries, deny paths (`NEXUSOS_DENY_PATHS`, absolute-only),
  nested-workspace protection, and `nexusos doctor` health checks
- typed configuration model (`NexusOSConfig`) with `nexusos.toml` and
  `NEXUSOS_*` environment overrides, validated at load time
- `nexusos config show` with `--effective` and `--json`

### Indexing kernel

- deterministic, workspace-scoped identifiers (`nxo_doc_*`, `nxo_chk_*`,
  `nxo_run_*`) stable across reindexing
- SQLite schema v1/v2 at `.nexusos/index.sqlite3` with FTS5 preparation,
  explicit versioned migrations, and typed refusal of incompatible future
  schemas
- transactional persistence (single-writer `BEGIN IMMEDIATE`, WAL mode) and an
  exclusive writer lock that reclaims stale locks
- incremental indexing with content-aware stale-index detection (mtime/size
  signatures)
- atomic, hardened state writes (`mkstemp` + `os.replace`)

### Retrieval and navigation

- ranked FTS5 full-text search (`nexusos search`) with bm25 ranking, source
  paths, line ranges, heading paths, and highlight-marked excerpts; safe query
  construction; `--json` output
- content navigation: `browse`, `read`, `recent`, `links`, `context`
- deterministic evidence packets via `nexusos context`
- result limits validated consistently across CLI, config, JSON, and MCP
  (search `[1, 500]`, browse `[1, 1000]`, recent/context `[1, 100]`)

### Linting

- workspace vault linter (`nexusos lint --workspace PATH`): broken wiki links,
  ambiguous links, invalid frontmatter, orphans, duplicate slugs, stale index,
  oversized files, empty documents, symlink escapes, files outside configured
  collections; `--json` output
- developer tooling lint (`nexusos lint`) runs ruff + mypy over the kernel

### MCP and local HTTP

- MCP server over stdio (`nexusos mcp`) exposing 8 tools: `status`, `search`,
  `browse`, `read`, `recent`, `links`, `context`, `index`
- MCP Streamable HTTP transport (`nexusos serve --transport streamable-http`,
  loopback by default, endpoint `/mcp`)
- read-only local inspection API and bundled UI (`nexusos serve --workspace`),
  token-protected `/api/*`, Host/Origin validation

### Developer tooling

- `nexusos demo` — scripted end-to-end walkthrough
- `nexusos version`, `nexusos lint --tool`, `nexusos lint --json`
- clean CLI errors with correct exit codes (1/2)

## What was fixed in the v0.1 train

### Shipped in v0.1.0-alpha.2 (commit `62b00f5`)

| Finding | Severity | Fix |
|---|---|---|
| F1 | HIGH | O(n³) heading-path hang in `nexusos index` — single-pass O(n) heading walk; a 5,000-heading file indexes in under a second |
| F2 | HIGH | Silent unreadable-directory skip — discovery surfaces `unreadable_directory` warnings and doctor fails its `source_dirs_readable` check |
| F-01 | MED | Temp-file symlink overwrite — unpredictable `mkstemp` names + `os.replace()`; `init --adopt` refuses a `.nexusos` that is a symlink, regular file, or already seeded |
| F-02 | MED | Host-header / DNS-rebinding exfiltration over serve — non-loopback Host rejected (403), per-process `X-NexusOS-Token` on `/api/*`, foreign Origins rejected |
| FD1 | MED | Stale-index detection missed content-only edits — mtime/size signatures instead of path sets |
| FD2 | MED | Root-level files excluded by default — globstar matches zero-or-more directories |
| F3 | MED | Raw CLI tracebacks on config/init/serve — clean `Error: ...` messages with exit codes |
| F4 | MED | Read-only index DB mislabeled corrupt — permission-error detection + read-only URI opens |
| F5 | MED | `NEXUSOS_*` env override type validation — validated at load time, error names the variable |
| F7 | MED | Discovery warnings counted but never surfaced — persisted in `index_runs.warnings_json` (schema v2) |

issues #4–#9 and resolved in the same change; no release-blocking security
finding remains.

| Finding | Severity | Fix |
|---|---|---|
| F-03 | P0 | Path-safety TOCTOU in the indexer read path — reads re-resolve the path against the workspace boundary immediately before opening (`read_source_text_safe`), refuse escaping symlinks, open with `O_NOFOLLOW` where supported |
| F-05 | P0 | Relative `NEXUSOS_DENY_PATHS` resolved against CWD — relative entries ignored with a one-time warning; only absolute entries match |
| F-06 | P0 | Unbounded/negative result limits — shared bounds validated across CLI, config, JSON, and MCP |
| F-07 | P0 | Dead `check_symlink_escape` defense — wired into `nexusos doctor` (warning) and `nexusos init --adopt` (refusal) |
| F-08 | P0 | Non-loopback bind for unauthenticated MCP Streamable HTTP — refused unless `--allow-non-loopback` / `NEXUSOS_ALLOW_NON_LOOPBACK=1` |
| F-09 | P2 | `.nexusos/index.lock` created owner-only (`0600`) instead of world-readable |
| F-10 | P2 | Kernel-data HTTP server no longer embeds the per-process API token in the unauthenticated root page on non-loopback binds |
| F-11 | P2 | Byte-for-byte source-immutability tests across CLI, HTTP `/api/documents`, and MCP stdio read/search, plus HTTP path-traversal tests |
| F-12 | P2 | Index SQLite database (and `-wal`/`-shm`) tightened to owner-only (`0600`) on writable open |
| F-13 | P2 | Search terms length-bounded (`MAX_SEARCH_TERM_LENGTH`) in the shared service layer and MCP `search` tool schema |
| F-14 | P2 | `docs/security-model.md` expanded into a full threat model; `SECURITY.md` names the concrete private advisory URL |

## Upgrade notes

See the full [install and upgrade guide](../install.md#upgrade).

- Run `nexusos index` once after upgrading — applies the schema v1 → v2
  migration. Read-only commands never migrate.
- `nexusos serve` HTTP API callers need the per-process `X-NexusOS-Token`
  header plus a loopback `Host`.
- `init --adopt` is stricter about existing `.nexusos` entries.
- Root-level Markdown is now indexed.
- Deny paths must be absolute; result limits are enforced; non-loopback MCP
  bind is refused unless explicitly allowed.

## Known issues and limitations (v0.1)

### Not implemented in v0.1 (post-v0.1 direction)

- Embeddings / vector database
- Source mutation through MCP (the MCP server is read-only by design)
- Ingestion connectors (web/PDF/external services)
- Guarded source writes / mutation API
- Cloud features, OAuth, multi-user, sync, hosted MCP

### Release-train limitations (tracked)

- macOS/Windows clean-install validation pending (RC-02); CI runs the full
  suite (unit + integration + security + contracts) on all three OSes ×
  3.11/3.12/3.13 and is green on `main`
- PyPI publication pending (RC-01; maintainer-only credentials)
- MCP Streamable HTTP is unauthenticated — loopback-only by default; do not
  expose it to an untrusted network without an external security layer
- The inspection UI ships as a single static `index.html`; no JS asset bundle
